# M1 API and orchestration contract

This is a prepared M1 vertical slice, not full V1 or the M3 optimizer. It evaluates
one selected unchanged seed against an explicitly synthetic immutable snapshot.
`execution_mode` is always `seed_evaluation`. Resume creates a new fenced attempt
and reevaluates from the beginning; it does not promise optimizer checkpoint resume.
The four original seeds remain unchanged. Slow/broken E2E strategies exist only
when the operator explicitly adds `--with-e2e-fixtures` to bootstrap.

## Runtime and startup

Python API/orchestration dependencies are locked separately in
`backend/requirements.lock`. The quant engine belongs to the isolated evaluator
image, never the API environment. Required environment:

- `DATABASE_URL`: PostgreSQL URL using psycopg, never SQLite.
- `SECRET_KEY`: randomly generated secret, minimum 32 characters; no built-in default.
- `STORAGE_ROOT`: persistent private filesystem shared by API and orchestration.
- `TRADEGRAD_RUNNER_STATE_DIR`: trusted persistent runner locks/tombstones, shared
  by workers/reconciler controlling the same Docker host.
- `EVALUATOR_IMAGE`: prebuilt local evaluator image, default `tradegrad-evaluator:v1`.
- `WORKER_CONCURRENCY`: default 1; deliberately bounded before increasing capacity.
- Optional `CORS_ORIGINS`: JSON array. Same-origin reverse proxy is preferred.

From the repository root, with the API environment active:

```sh
alembic -c backend/alembic.ini upgrade head
python -m backend.app.bootstrap --email "$E2E_EMAIL" --password-env E2E_PASSWORD --with-synthetic-fixtures
uvicorn backend.app.asgi:app --host 127.0.0.1 --port 8000
python -m workers.research dispatcher
python -m workers.research worker
python -m workers.research reconciler
```

Run the final four commands as distinct supervised processes. Bootstrap reads a
password from the named environment variable, creates no account on server startup,
and never changes an existing user's password. Passwords require 12+ characters.
An E2E second account can be provisioned with `--email "$E2E_OTHER_EMAIL"
--password-env E2E_OTHER_PASSWORD --with-synthetic-fixtures`.

## HTTP

All routes are under `/api/v1`. Except login and minimal health, they require
`Authorization: Bearer <access_token>`. Tokens expire after 30 minutes by default.
The template's Argon2/JWT/auth dependency pattern is adapted with attribution in
`backend/NOTICE.md`; email, public signup and password recovery are not M1 features.

| Operation | Route | Semantics |
| --- | --- | --- |
| Login | `POST /login/access-token` | OAuth2 form `username`, `password`; returns token and `expires_in` seconds |
| Current user | `GET /users/me` | Current active user only |
| Datasets | `GET /datasets`, `GET /datasets/{id}` | Owner-scoped immutable snapshots, source/coverage/synthetic labels |
| Strategies | `GET /strategy-versions`, `GET /strategy-versions/{id}` | Owner-scoped immutable strategy metadata and source detail |
| Submit/list | `POST /runs`, `GET /runs` | POST requires `Idempotency-Key`; 202 accepted or replay |
| Run detail | `GET /runs/{id}` | Persisted authoritative status and attempt history |
| Cancel | `POST /runs/{id}/cancel` | 202; remains `cancel_requested` until confirmed stopped |
| Resume | `POST /runs/{id}/resume` | 202; failed/cancelled/interrupted only, old sandbox stopped, new generation |
| Events | `GET /runs/{id}/events` | Authenticated durable ordered SSE, reconnectable |
| Artifacts | `GET /runs/{id}/artifacts`, `GET /artifacts/{id}/download` | Owner-gated, checksum verified, forced attachment download |
| Health | `GET /health/live`, `GET /health/ready`, `GET /status` | Liveness, migrated DB readiness, authenticated role heartbeats/own pending outbox |

Lists return `{data, count}` with `offset >= 0`, `1 <= limit <= 100`. Errors return
`{code, message, details, correlation_id}`. Authorization failures intentionally
return 404 for another owner's resource, including events and artifact bytes.
Unknown or expired bearer tokens return 401.

Run body:

```json
{
  "task": "cn_time",
  "dataset_version_id": "a valid owned snapshot UUID",
  "strategy_version_id": "a valid owned strategy UUID",
  "start_date": "2024-01-02",
  "end_date": "2024-04-27",
  "profile": "corrected_explicit_config"
}
```

Tasks are `cn_time`, `us_time`, `cn_cross`, `us_cross`. Ranges are `[start,end)`.
Task/strategy/market and immutable snapshot bounds must agree. The API accepts no
client filesystem paths. Same owner's same key/body returns the original Run;
changed body with that key returns 409. Keys are scoped to an owner. Submit/resume
both enforce active-run quotas under a PostgreSQL advisory lock.

## SSE and reconnect

Fetch streams with the existing Authorization header, never a token in a URL.
Each durable event is `id: <seq>`, `event: <type>`, and a JSON envelope containing
`schema_version`, `run_id`, `attempt_id`, `seq`, `occurred_at`, `type`, `payload`.
Pass `after_seq` or `Last-Event-ID`; the server resumes strictly after the greater
cursor. `follow=false` performs a bounded replay. Terminal runs close after all
committed events are delivered. Reconnecting does not recreate or restart a run.
Fresh database ownership/active-account and token-expiry checks protect streams.

## Reliability and isolation

A single PostgreSQL transaction records Run + initial event + outbox. The dispatcher
locks pending outbox rows and calls the pinned Procrastinate external-psycopg
connection API, so enqueue and delivery marker commit/rollback together. Duplicate
deliveries still pass through generation-aware, row-locked business claims.

ExecutionAttempt carries a random lease token, expiry, generation and sandbox ID.
Every write validates the current run generation, active attempt, lease token and
unexpired lease. Lease expiry alone never authorizes restarting. Reconciliation
must stop the named sandbox and confirm its absence before marking the old attempt
interrupted/cancelled; resume then creates a different attempt UUID. Persistent
runner tombstones prevent a delayed old worker from creating a sandbox after stop.
Stale queue deliveries, including a crash before business claim, are recovered
using Procrastinate worker heartbeats; they cannot bypass the business claim fence.

The worker stages hash-verified inputs by resource ID, filters bars to the exact
requested date range, and invokes only the fail-closed Docker runner. There is no
local subprocess fallback for strategy execution. Logs are bounded/redacted, and
artifacts are immutable, namespaced by Run/Attempt, and hash-checked on download.
All downloads use attachment disposition and sandbox CSP, not same-origin HTML.

Native strategies share their evaluator process with AKQuant. Results explicitly
carry `evaluation_mode=native_akquant`,
`result_trust=native_strategy_and_engine_share_process`, and evaluator image digest.
They are research observations, not a separately trusted execution ledger. Artifacts
include metrics, redacted logs and provenance, not fabricated chart/trade series.

## Operational limits and validation

The API has bounded DB connection/pool/statement/lock timeouts. Login has a local
per-process brute-force backstop; production proxies must supply a shared rate
limit for multiple processes/public exposure. TLS/reverse proxy, backups and
cross-host object storage remain deployment responsibilities. The local storage
backend requires shared persistent storage on one Docker host.

`python -m backend.app.export_openapi` regenerates the deterministic
`packages/contracts/openapi.json` without a DB connection. Frontend generated types
come from this schema, not hand-maintained duplicate request definitions.

Offline checks: `python -m pytest backend/tests -q`, Ruff, compileall and Alembic
`upgrade head --sql`. Real integration: set `TEST_DATABASE_URL` and run
`python -m pytest tests/integration -q`. Missing PostgreSQL is an explicit skip;
SQLite or an unreachable configured PostgreSQL URL is an error, never a fallback.
Live PostgreSQL, Docker and Playwright acceptance remain separate mandatory gates.
